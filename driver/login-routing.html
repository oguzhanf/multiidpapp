The application chooses the directory before sign-in

The decision starts in AccountController.Login. It calls RegistrationRuntime.Route, which uses configured domains and, in App02, approved partner records. The controller then challenges the selected OWIN provider. Entra authenticates the user at that provider.

Email form→AccountController.Login→RegistrationRuntime.Route→workforce / external challenge→Entra → callback → app approval

01 · The login POST starts the selected challenge

The home page posts the email to /Account/Login. This action requires HTTPS and an anti-forgery token. The routing result selects the named provider; login_hint only pre-fills the sign-in experience.

Controllers.cs · AccountController.Login

  • Challenge(..., "workforce") starts the workforce provider.
  • Challenge(..., "external") starts the External ID provider.
  • AuthenticationProperties.RedirectUri = "/Benefits/Index" is the application destination after authentication. The Entra protocol callback is configured separately in step 03 below.

The returned HTTP 401 triggers the selected middleware's authentication challenge and browser redirect. This action does not validate a password, search both directories or grant app access.

What makes a dynamically registered partner domain eligible?

HasApprovedPartnerDomain requires App02, a redeemed organizational invitation, the bound workforce identity and separate home tenant, and exactly one current matching partner approval. A pending invitation does not activate this route. A route for one domain grants no access to other users at that domain.

For an App02 B2B partner, the app starts at the workforce resource tenant. Entra handles authentication with the partner's home organization; the application receives the workforce resource-tenant token.

04 · The callback validates identity before app access

Microsoft returns an authorization code to the selected callback. The MSAL adapter redeems it with the protected PKCE verifier. Katana handles the protocol response and nonce; the strict token validator checks signature, expected issuer, audience and lifetime.

05 · Microsoft 365 discovery happens during invitation

In App02, an approved workforce Employee with admin invites a business contact. InviteAsync calls ResolveOrganizationAsync to classify the recipient domain. Known personal domains such as Gmail and Hotmail skip organizational discovery.

RegistrationServices.cs · ResolveOrganizationAsync

Loading source…
  • A recognized separate organizational tenant selects B2B onboarding in workforce and the App02 Partner role.
  • A personal contact selects customer provisioning in External ID and the target app's External role. A dependent invitation uses Dependent; organizational addresses are rejected for that purpose.
  • The discovery result is a candidate tenant. It proves neither this person's membership nor a Microsoft 365 licence. Signed home-issuer proof and confirmed app approval are required later.
  • A discovery service error stops the invitation; it does not silently reclassify the account.
How the invitation selects the first sign-in provider

The server records the invitation's bound source and recipient identity. RegistrationController.Begin challenges that source directly. This lets the first partner use workforce before their redeemed approval activates normal home-page domain routing.

RegistrationControllers.cs · Begin

Loading source…

After confirmation, the saved partner approval can activate the dynamic App02 domain route. New personal recipients verify email and create a password, then use the bound external provider and confirm registration. Existing recipients can sign in with their existing account before confirmation.

Sampleapp01 has no organizational partner registration or admission. Its employee/dependent flow uses workforce for the sponsor and External ID for the dependent.

06 · An authentication failure stays in the selected realm

The failure handler redirects to /Account/Failure. It never issues a challenge to the other provider. A wrong password, missing assignment, expired approval or Conditional Access denial is resolved at the selected boundary.
